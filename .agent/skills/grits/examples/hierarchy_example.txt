# Grits Hierarchy & Migration Example

## 1. Creating a Hierarchy from Scratch
Agents can build deep task structures using dot-notation IDs.

```bash
# Create the Epic
gr create "UI Overhaul"
# ✅ Output: Created issue gr-nfx4h8

# Create sub-tasks
gr create "Implement login screen" --parent gr-nfx4h8
# ✅ Output: Created issue gr-nfx4h8.1

gr create "Add social auth" --parent gr-nfx4h8.1
# ✅ Output: Created issue gr-nfx4h8.1.1
```

## 2. Migrating Issues into a Hierarchy
If an issue was created standalone or used as a blocker, it can be "promoted" into a hierarchy.

```bash
# Existing standalone issue
gr create "Fix css alignment"
# ✅ Output: Created issue gr-standalone123

# Migrate it into the UI Overhaul epic
gr dep add gr-standalone123 gr-nfx4h8 --migrate
# ✅ Output: Migrating gr-standalone123 -> gr-nfx4h8.2
# ✅ Output: Linked gr-nfx4h8.2 to gr-nfx4h8 (type: parent)
```

## 3. Advanced Linking
Links can be used for non-hierarchical blocking relationships.

```bash
# Link without renaming/migration
gr dep add gr-nfx4h8.1 gr-db123 --type blocks
# ✅ Output: Linked gr-nfx4h8.1 to gr-db123 (type: blocks)
```
